# WRITER-TOOLKIT v0.3 — CORE CONTRACT

Status: distribution-compiled summary from the canonical Architecture Spec and Build Spec.

## Always-active Core
- Author Sovereignty.
- Authority / Decision / Artifact State model.
- Evidence Policy.
- Change classification.
- Core Development Loop:
  UNDERSTAND → INSPECT → PLAN → CREATE → TEST → AUDIT → RECORD → CHECKPOINT.
- Knowledge Discipline.
- Causality:
  CAUSE → CHOICE/ACTION → CONSEQUENCE → NEW SITUATION.
- Persistence semantics:
  MANUSCRIPT / STATE / DIGEST are separate.
- Gate and runtime status semantics.
- No Unauthorized Artistic Optimization.

## Decision states
UNKNOWN | OPEN | DEFERRED | PROPOSED | ACCEPTED | REJECTED

DEFERRED is not permission. If it becomes load-bearing:
AI MUST STOP → present issue/options → obtain the required decision, unless autonomous determination was explicitly authorized by project rules.

## Artifact authority
MANUSCRIPT = authority for literal text.
STATE = authority for project decisions and execution state.
DIGEST = navigation only.

## Runtime neutrality
Core does not assume a filesystem, RAG, API, Python, long context, exact counting, external agents, or file export. Those are Adapter capabilities.

## Specificity firewall
Project-specific values → Project State.
Domain-specific rules → Conditional Modules.
Runtime constraints → Adapters.
Test scenarios → Tests / Stress Harness.
