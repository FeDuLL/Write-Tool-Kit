# Development History

## v0.1.x — foundation

The early architecture established author sovereignty, authority/state separation, causal consistency, knowledge discipline, hidden-world/reveal controls, persistence, audit, and cross-media separation.

Stress tests exposed several false universals: secrecy is not automatically fair, hidden ontology must not replace personal drama, semantic leakage must be controlled, and test parameters must not become Core rules.

## v0.2 — production workflow

The system gained Creative Brief, Genre Contract, scope handling, long-form production, synopsis and sequential production, revision ripple control, and pre-publication audit concepts.

Cross-model experiments exposed different failure modes in workflow control, artifact persistence, style handling, and self-audit.

## v0.3 — operational architecture

The current version formalized:

- MANUSCRIPT as literal-text authority;
- STATE as authority for accepted decisions and execution state;
- DIGEST as navigation only;
- explicit scope records;
- Style Baseline and Style Lock;
- runtime capability profiles;
- active-module declarations;
- AI-DECIDED authorization;
- deviation records;
- audit evidence and audit independence;
- FORM-aware routing;
- conditional modules;
- adapters;
- canonical bootstrap;
- Native Skill and Universal TXT distributions;
- canonical schemas;
- anti-drift validation.

## Architectural rule

A mechanism belongs in Core, a project-specific value belongs in State, a domain rule belongs in a module, a runtime constraint belongs in an Adapter, and an experiment belongs in Tests.
